# 培养计划学分问答：完整交付

## 分工与当前入口

- **B：共用教务拓展与课表兼容**。只更新原拓展，0.3.3 同时支持课表与“计划完成情况”；修复教务不重载切换造成按钮残留、课表读取错误。手机可上传导出的 JSON，不要求手机装拓展。
- **C：培养计划与通识选修规则**。规则继续使用 `knowledge/degree/cs-2025/plan-rules.md`（C08，4805f6e）。六模块选四、所选四个各至少 2 分；艺术要求单独核对，不捏造课程所属模块或学校认定，不作毕业资格判断。
- **D：私有存储、授权与 Agent 导入**。固定平台身份查唯一空间；`degree:read` 读取，独立 `degree:write` 预览/确认保存；旧授权不会自动升级。原课表、日历、身份流程保留。

用户流程：教务“计划完成情况”导出 `degree-progress.json` → 发给 Agent → 核对完整分类预览 → 本人明确确认 → 后端保存并读回版本 → 对话查询缺分。
旧 `/tools/degree` 只提供简短说明，不再提供另一套培养计划业务 UI。

当前学分提示块为 `deploy/genios-workflows/degree-progress-qa-fit-live.txt`。
其余 `append` / `compact` 提示是历史设计参考，不应叠加到正式 Agent。
两个 OpenAPI 文件定义读取及预览/确认工具；不要用旧独立页面保存替代本人的对话确认。

## 数据口径

只导出学校总览、分类要求/实修/状态及分类在读汇总。不保存课程成绩、课程明细、姓名学号、审核人、浏览器凭据或整页 HTML。

0.3.3 可选字段 `school_in_progress_credits` / `school_direct_in_progress_credits`：明确在读才统计，未知不补零。直属在读不会分配到六个通识子模块。
教务实修可能含在读，扣除已明确在读后的数值仍不是学校正式认定的已取得学分。
旧 JSON 不含这些字段时保持未知；更新拓展、刷新教务、重新导出，并由本人确认替换，不能自动改旧报告。

通识总学分差额与“四选六”的模块覆盖差额分开算。已有两个达标模块，还需两个；补艺术模块后只再需一个，不额外重复计算艺术。
父子分类不累加；父级 7 / 子类合计 4 的差额仅在明确直属在读 3 分时解释，不猜归属。
