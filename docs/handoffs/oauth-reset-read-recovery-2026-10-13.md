# 清除后 Agent 私人读取授权恢复：进行中

本记录是 PR #21 提交后用户再次报告的另一条故障；不要把原空间绑定成功当成课表、日历读取验收。当前修复尚未完整闭环，正式 Web 仍为 v0.2.25，新的读取规则仅保存到草稿，未发布未验收版本。

## 实证

- 草稿以用户自然问法读取课表，真实调用树为 `attest_my_platform_identity → read_my_demo_records`，后者返回 401 `AUTH_REQUIRED / Identity storage rejected this operation`。本轮日历读取也复现同一 401。
- 原腾讯云只读聚合查询返回：OAuth grant 行数 0、未过期 grant 0、有效来源浏览器 grant 0；固定平台空间映射数 1。不查询令牌值、姓名、课程或他人身份。
- 原浏览器工具站直接读取本人课表成功（版本 1），日历也读取成功（当前无未完成事项）。因此不是课表/日历 JSON 消失，也不是浏览器绑定失败。
- 原库清除后的学校插件授权缓存没有同步恢复；学校平台仍发送后端无法匹配的 OAuth。后端身份签名校验已通过，失败点在私有 SQL `verify_grant` 的 grant/来源会话检查。不能撤掉守卫或拿浏览器 Cookie 冒充 Agent 授权。

## 已实现部分

- `genios_identity.py`：只有固定身份和签名验证已经通过、实际 OAuth grant 检查返回 401 AUTH_REQUIRED 时，转换为标准 OAuth `invalid_token`；身份/证明错误、错账号仍原样拒绝，不能混称为重新授权即可解决。
- `oauth_pilot_site.py`：invalid_token 401 返回 `WWW-Authenticate: Bearer realm="campus-oauth", error="invalid_token"`，保留 no-store。依据 [RFC 6750 §3.1](https://www.rfc-editor.org/rfc/rfc6750#section-3.1)，不给任何私人数据或假空列表。
- 新增 HTTP/隔离真实 PostgreSQL 回归：失效 grant 在课表、摘要、日历三个路由均拒绝并挑战；同空间新授权恢复三个读取，无新 owner；错误签名不是 invalid_token。其余身份、OAuth、持久授权回归保持通过。
- 草稿：明确 `attest → 课表/日历实际读取 → 本次结果直接回答`，禁止只说将读取就结束；不因新会话自动读私人摘要；401 不通过重绑、重建或换身份解决。原非空业务段保留，规范化后 65,522 UTF-8 字节；保存后重开编辑器确认规则仍存在。

本地回归 76 项通过、1 项未运行：唯一排除项 `test_contract_examples_and_no_mcp_registration` 在原测试依赖目录缺 Windows `pywintypes` 时无法导入 MCP，初次运行报依赖错误，不作为通过。最终读取规则静态测试另 6 项通过。
