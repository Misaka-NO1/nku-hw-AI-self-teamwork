## 4. 课表问题是怎么修复的

原问题是模型手抄完整课表 JSON 时产生 1604/1605 字符的损坏文本，正确夹具应为 1606 字符。后端拒绝坏 JSON 是正确行为，不应该补括号或放宽契约。

本轮改为确定性参数生成：

```text
Start.fixture_id（String，必填）
  → 代码01：只接受 timetable.demo
      取固定公开虚构夹具
      query_json = JSON.stringify(fixture)，只序列化一次
  → 插件01：campus-tools-dev / platform_validate_timetable
      query_json 直接引用 代码01.query_json
      “校验 isError 作为异常”开启；“异常忽略”= 无
  → End.result（Object）
      直接引用 插件01.structuredContent
```

- 不让大模型生成或抄写课表 JSON。
- 不加入任意 URL、文件读取、真实课表、令牌或身份参数。
- 保留真正的 null、空数组、中文及原始类型，不用字符串 `"null"` 替代空值。
- 未知 `fixture_id` 抛出 `UNKNOWN_FIXTURE`，不自动改成演示夹具。
- 刷新读回验证了三条执行边、输入引用、错误开关和 End 对象映射已保存。会话过期期间有部分修改未保存，重新登录后已恢复并验证。
