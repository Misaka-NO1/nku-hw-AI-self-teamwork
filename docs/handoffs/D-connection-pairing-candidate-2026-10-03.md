# D：NK-GeniOS 连接凭证 + 腾讯云本人配对候选

2026-10-03。状态：**可运行的隔离本地原型，尚未接入学校或云端，不是成品公告**。

## 为什么这条路线值得继续实施

当前学校实际授权请求没有PKCE challenge，严格OAuth候选不能接通。直接删除PKCE校验会改变原认证保护；在URL后面固定补challenge也不能让平台在兑换时持有同事务verifier。

新候选把两件事分开：学校现有授权码流程仅创建**不带用户身份、没有个人数据权限**的连接；个人数据访问由用户在已核验的腾讯云浏览器会话中另行批准。原 `/oauth/*` 严格PKCE路径、15张身份表、005/003/公开内容服务和主Agent发布状态保持不变。

此候选借鉴[设备授权流程 RFC 8628](https://www.rfc-editor.org/rfc/rfc8628.html)的跨设备配对思路：显示短码、另一个可信会话登录、本人核对和同意。**不是说学校支持RFC 8628，也不声称本原型是该标准的实现。** 此处是需要独立审核的新连接/数据授权协议。

## 用户实际使用方式

```text
NK-GeniOS 调用插件
  → 学校后台保密持有一枚无身份的待配对连接凭证
  → Agent 显示配对码和固定复核页入口（不显示Bearer或密码）
  → 用户在工具站登录腾讯云，手动输入当前Agent显示的码
  → 页面显示当前账号、只读权限、到期时间和防钓鱼警示
  → 本人核对同一个Agent会话，明确确认
  → 后端一次性绑定该连接到已核验会话的owner
  → 回到Agent继续查询；后端只读此owner已确认的虚构记录
```

工具站仍是登录/确认入口，不变成第二个聊天产品。用户不用填数据库地址，不需要在聊天中发密码、CloudBase Key、用户Bearer或真实课表。

## 原型已经证明的约束

| 阶段 | 所持凭证及权限 | 关键拒绝条件 |
| --- | --- | --- |
| 匿名引导码 | 90秒一次性码；不存owner | 错client/回调、额外owner或SYS_USERID、任何个人数据scope均拒绝 |
| 待配对连接 | 10分钟随机256位Bearer；只返回短码/配对状态 | 没有本人批准不能调用记录读取器；短码5分钟过期 |
| 本人复核 | 仅已批准两账号的可信会话；CSRF及Origin核验 | 预览不授权；复核回执60秒、绑定原会话，B不能使用A回执 |
| 明确批准 | 同一短码、同一会话、两个明确确认，原子改绑一次 | 重放、错误码、过期、第二owner竞争均拒绝 |
| 已配对只读 | 绑定owner和原登录会话；期限不超过连接/会话 | Cookie不能覆盖Bearer身份；退出/到期/撤销立即拒绝新读取，不回退公共夹具 |

本地数据库只存引导码、Bearer、短码与复核回执的摘要，不存客户端密钥/原文凭证。短码由高熵Bearer的用途分离摘要导出，可再次显示给持有此Bearer的学校客户端；不是后台数据访问Bearer。失败猜码会持久计数，每owner每5分钟最多5次，不因事务回滚或换登录会话清零。当前只是本地模型，不能当作已上线的分布式抗滥用设施。

模拟授权码被替换的用例：匿名引导码不携带攻击者owner，学校兑换产生新的待配对随机Bearer，原码只能成功兑换一次；在本人复核前没有任何个人数据。与“把已有owner的授权码直接放宽成无PKCE”不同。

## 不能省略的风险与真实验收

1. **配对码钓鱼。** 对方仍可能诱导用户输入其Agent显示的码。这是设备配对类流程的固有风险；需明确提示只输入自己当前Agent会话的码，复核账号/权限，禁止链接参数自动批准或模型代确认。人工确认不能声称彻底消除钓鱼。
2. **学校令牌隔离。** 必须实测学校在服务端保密保存Bearer、按用户隔离，不把它送进LLM或分享给同一插件的其他用户。若学校只提供团队共享令牌，这条路线不得开放个人记录。
3. **云持久事务。** SQLite通过的是本机多连接事务模型，不是CloudBase PG并发。独立PG schema/RPC候选已实现并通过嵌入式PostgreSQL测试，但尚未在CloudBase执行。云端部署、真实多连接并发和到期清理仍待完成，不能将PGlite单连接自动化说成云验收。
4. **数据来源。** 云适配只能从实际批准身份读取现有已确认记录，仍须固定虚构内容校验；不得从请求传入owner/workspace，不能把测试fixture verifier替换为“相信SYS_USERID”。
5. **权限及变更确认。** 部署并启用新数据授权路径/将插件绑定主Agent草稿前，需要负责人在行动时明确批准范围。只读先行，不注册commit/确认工具，不接真实成绩、不公开主Agent。不新增长期Key或购买资源。
6. **契约同步。** 原型没有注册进公共应用，所以没有修改既有schema。升为部署候选前必须按契约§7同步新请求/响应、fixtures、HTTP/PG正反例和A/B/C handoff；旧客户端不迁移。
7. **短期资源限制。** 当前后台Key到2026-10-04 18:21:48、默认测试域名有供应商提示，仍不是长期生产入口；不在本轮隐式扩大Key期限/账号范围。

- 本轮两文件：**56 passed**；完整后端：**559 passed**，107.02秒。存在Starlette TestClient的AnyIO弃用警告，不是测试失败。
