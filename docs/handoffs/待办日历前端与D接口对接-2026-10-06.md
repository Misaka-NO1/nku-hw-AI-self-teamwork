## 演示与真实记录严格分开

进入页面不会自动新建工作区、排期、保存或申请通知权限。未登录时提示正常登录，核验失败不展示旧账号数据。

点击“查看前端演示”后显示当前日期附近的虚构事项；所有变化仅在本页内存中，刷新/退出即清空。演示候选没有调用课表算法，也没有校验截止时间，只用于检查交互。此模式不会成为真实 API 错误时的自动降级结果。

真实模式优先读取日历扩展 API；只有其返回 404/501 才用现有 `GET /api/v1/tasks?workspace_ref=...` 读取原待办，并明确只读。原接口没有完成/取消/提醒字段，前端不假装已有这些能力；401/403/503、响应不合法等均显示错误，不自动换成演示。

## 请 D 确认并实现的接口草案

**以下路径和新增字段是前端适配方案，尚非已生效公共契约。** D 应按契约流程确认，或提供等价接口并同步修改 `calendar/api.ts`。不要仅部署前端便宣布全链路完成。

统一响应沿用 `ok / data / error / meta`，前端使用既有 apiClient，并自动将 snake_case 转 camelCase。身份来自现有 Cookie；workspace_ref 只作归属校验，不是身份证明。后端复用本人授权链路，不接新管理员系统。

### 1. 读取日历

`GET /api/v1/tasks/calendar?workspace_ref=当前授权工作区`

`data` 示例结构（notice 内部继续使用当前完整 NoticeDraft）：

```json
{
  "items": [
    {
      "task_id": "稳定任务ID",
      "revision": 1,
      "confirmed_at": "2026-10-06T09:00:00+08:00",
      "notice": {"title": "示意：此处实际返回完整 NoticeDraft，不是仅一个标题"},
      "calendar_revision": 2,
      "status": "pending",
      "scheduled_start": "2026-10-07T18:00:00+08:00",
      "scheduled_end": "2026-10-07T18:30:00+08:00",
      "reminder_minutes": 15
    }
  ],
  "capabilities": {"scheduling": true, "status": true, "reminders": true}
}
```

上述 notice 为结构说明，不是可提交夹具。实际必须包含现有 event、due、estimated_minutes、materials、source_spans、needs_confirmation 等完整字段。

- `calendar_revision` 是日历状态版本，与原始通知 revision 分开；初始可为 0。
- `status`：`pending / completed / cancelled`；缺能力时对应 capability=false，不先开放按钮。
- `scheduled_start/end` 必须同时为 null 或同时为有效且递增的带时区时间。null 表示未排期。
- `reminder_minutes`：null 不提醒，0 开始时提醒；前端提供 5/15/30/60 分钟选项。
- 原始 `notice.due` 不因改期被改写。固定活动仍可由 notice.event 显示，不擅自改期。
- 先返回当前本人完整事项；量大时需新增分页与前端联调，不能静默截断却让摘要冒充全量。

**FastAPI 注意：静态 `/calendar` 路由必须注册在 `/{task_id}` 之前，避免被当作 task_id。**

### 2. 读取本次候选

`GET /api/v1/tasks/{task_id}/calendar/candidates?workspace_ref=当前授权工作区`

```json
{
  "candidate_slots": [{"start":"2026-10-07T18:00:00+08:00", "end":"2026-10-07T19:00:00+08:00", "duration_minutes":60}],
  "needs_confirmation": [],
  "coverage": {"completeness":"unknown"}
}
```

候选由 D 读取该任务及本人课表，再调用 B 算法产生。前端只将足够长的窗口转换为从窗口起点开始、恰好等于 estimated_minutes 的工作区间；耗时未知不能生成区间。原任务仍有待确认字段时由 D 返回澄清项。

候选需要结合当前日期、截止、最早开始、课程和未完成的已排任务；过期历史演示通知不自动平移成新通知。固定不可改期的活动不显示改期候选。后端保存时必须重新检验窗口及版本，不能相信浏览器传的时间一定有效。

### 3. 明确确认后写入日历状态

`POST /api/v1/tasks/{task_id}/calendar`

Header：现有 `X-CSRF-Token` + `Idempotency-Key`；身份 Cookie 随同源请求发送。

```json
{
  "workspace_ref": "当前授权工作区",
  "expected_revision": 2,
  "status": "pending",
  "scheduled_start": "2026-10-07T18:00:00+08:00",
  "scheduled_end": "2026-10-07T18:30:00+08:00",
  "reminder_minutes": 15
}
```

成功返回更新后的 CalendarTask，且随后 GET 可读回同样状态；时间可以标准化为等价 UTC。前端比较时间戳，不要求同一时区字符串逐字相同。

D 必须实现：本人归属、原任务存在、版本 CAS、幂等、事务持久化、时间/耗时/截止与课表校验、状态转移。网络重试不能重复记录；修改后旧 revision 返回409。取消为可恢复状态，不物理删除原通知。完成/取消后空档查询释放工作区间，恢复时重新检查冲突；未排期任务的 due 不占时间。

现有默认模式有固定夹具门禁。通用输入放行方案由 D 明确设计，不全局删除校验；不要为配合前端把 fixture 内容偷偷改成今天。

### 4. Agent 提醒对接

前端已经从列表计算页面摘要。D 可另提供本人摘要工具，输出未完成、今日、逾期数量及下一项，供 Agent 首次回复前实际调用。

## 提醒能力边界

页内摘要/即将开始提示无需权限。桌面通知需要支持的安全上下文、用户主动授权，并受浏览器后台节流、登录有效期和页面存活影响；当前页面去重不是跨设备后台队列。

导出 .ics 后用户需导入系统日历，并核对应用是否导入 VALARM、是否打开通知。关闭网页后可由日历应用提供提醒，但不是本项目保证的云推送；改期、完成、取消不会自动同步到已导入副本，需要用户更新。

依据：[MDN Notifications](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)、[MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html)。

## 构建、部署与验收

使用原 `Build-Visual-Tools.ps1` 分别构建公开/身份产物，API 同源 `/`。更新两服务前端导航，身份服务包含新页面；公开服务仍不托管个人日历，只链接身份服务。包含页面路由白名单修改的身份后端也需随包更新；普通代码更新不重复执行首次建库 SQL。

本地前端入口：`/tools/calendar`，点击“查看前端演示”。UI验证仅证明前端，不证明数据库或学校工作流。

D 接通后共同测试：

1. 本人登录 → 真实待办列表 → 日期与摘要一致。
2. 新通知 → 真正课表候选 → 选择、勾选确认 → 保存 → 刷新/服务重启读回。
3. 完成/取消/恢复 → 日历摘要与下一次空档查询一致。
4. 网络响应丢失重试、旧版本、跨账号、登录过期、不合法时间正确拒绝。
5. 提前提醒/0分钟/不提醒、完成事项不提醒；不要用“申请权限成功”替代实际通知触发验收。
6. ICS 导出落盘、导入实际日历应用后提醒；若应用不支持，明确记录，不声称全部环境可用。
7. 主 Agent 首次回复摘要、跨功能切换；页面自动打开提醒与关闭后推送分别验收。

本轮未改动学校正式配置、腾讯云部署或数据库，也未自动提交 PR。
