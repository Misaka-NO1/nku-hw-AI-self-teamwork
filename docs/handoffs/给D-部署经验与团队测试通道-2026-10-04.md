# 给 D：部署经验与团队测试通道

日期：2026-10-04。本文件只记录实际配置、踩坑与验收边界，不包含密钥、密码、学号或登录会话。

## 1. 项目入口与架构

NK-GeniOS 的 Agent 是用户对话入口。学校插件/工作流调用腾讯云后端；后端处理公开资料索引、课表时间计算与已授权演示数据。外部工具页只承担必要可视化和受控确认，不是另做一个取代 Agent 的六功能网站。

共用入口、根地址、运行命令见 [TEAM-DEVELOPMENT-ENTRY.md](TEAM-DEVELOPMENT-ENTRY.md)。地图与课表导航只保留两个入口；复习资料仍能逐文件下载，相关深链接和后端接口没有被删除。

| 层级 | 当前状态 | 不能据此声称 |
| --- | --- | --- |
| 学校主 Agent Web | v0.2.7，指定用户访问 | 全校公开、所有团队成员已登录验收 |
| 公开内容服务 | 部署009，r10；34点位、91照片、33原PDF | 今日花况、官方核验目录、原PPT |
| 身份演示服务 | 部署016，r14；两名批准的普通测试用户 | 真实教务课表/成绩已接通 |
| 原 MCP 服务 | 005 保留 | 健康探针通过等于全部业务通过 |

正式版本、学校草稿、云服务版本是三件事。Git/PR 合并也不会自动更新学校配置或腾讯云部署。

## 2. 部署操作顺序

1. 先跑本地测试、检查契约和公开文件范围，再构建。不要把本地 SQLite、会话文件、`.env`、密码或 service_role Key 提交到 Git。
2. 用 `deploy/Build-Visual-Tools.ps1` 明确选择 public/identity。公开构建输出 `frontend/dist`；身份构建输出 `frontend/dist-identity`，不得互换。
3. 脚本固定 `VITE_API_BASE_URL=/`，设置两个服务之间的地图/课表链接，并恢复运行前的进程环境。`VITE_*` 会进入浏览器，只能放公开配置。
4. 用相应后端打包脚本生成新包名。运行时 `BUILD_ID` 必须逐字等于包 manifest 的 build_id，不靠放宽校验解决不一致。
5. 更新目标服务的代码包，保留现有后台凭证和数据库。常规代码更新不重新执行首次建库 SQL，不新建重复表，也不覆盖其他服务。
6. 等待部署正常后检查 `/healthz` 的真实 build_id，再检查页面、API、学校插件和聊天。构建成功、云端“正常”、工具调试绿勾都不是业务验收的替代。

部署008/r9、015/r13曾漏填前端 API 地址，页面出现配置错误；修正同源 API 地址后重建为009/r10、016/r14。新的构建脚本用于避免这个配置遗漏。详情见 [D12证据](../evidence/platform/D12-conversation-delete-and-tool-navigation-2026-10-04.md)。

## 3. 常见错误如何区分

| 现象 | 处理与边界 |
| --- | --- |
| 学校页面空白、503或删除历史 Network Error | 先重新打开/登录学校页面；不能断言所有503都是会话过期。重登后已验证只删除指定测试会话“6”，刷新后仍消失，其余17条保留。没有修改学校服务器代码。 |
| Selected model is at capacity | 学校模型负载问题，不能据此判断云数据库坏了；重试或由负责人选可用模型。 |
| 腾讯云测试域名访问提示 | 用户正常确认访问；不通过伪造 Cookie/Header 绕过提示，也不把该提示当项目登录页。正式自定义域名需另行准备，当前未购买。 |
| 课表显示 AUTH_REQUIRED | 登录会话过期或未登录，需正常授权；不是 API 地址漏配。最近导航验收未重新登录读取个人演示记录，不能声称新增了这项证据。 |
| 平台调试成功，但返回 ok=false | 业务失败；保留 error、request_id、范围提示，不生成成功答案。 |
| ok=true，但候选列表为空 | 先检查 needs_confirmation 和覆盖范围；空列表不等于字段遗漏，也不能让模型手算“补上”。 |
| 账号搜不到 | 姓名与学号分别核对，不添加相似人员；请该成员先正常登录 NK-GeniOS，再查目录。尚未确定原因时不要断言是未注册。 |

## 4. 平台接口联调经验

平台兼容工具外层只有 `query_json` 字符串，内部是原业务对象编码一次。不要传对象、套 payload、编码两次，或把真正 null 改成字符串“null”。REST 景点查询使用唯一参数 `query=<URL编码JSON>`，与平台工具外层不同。

长课表固定夹具通过 `WF_D06_TimetableFixture_Test` 生成和校验，避免模型抄长 JSON。用户指定未知 fixture_id 时原样拒绝，不能替换成成功夹具。时间候选由后端算法产生；截止时间不是整段忙碌时间，缺耗时或确切时刻先澄清。

OAuth 使用当前授权身份，不以聊天里的姓名、学号、SYS_USERID 文本替代身份。学校平台名单不等于腾讯云测试用户名单；数据库 API Key 也不是 OAuth client_secret。当前只批准两个云测试账号和虚构数据，团队协作不自动扩大真实个人数据使用范围。

## 5. 资料与赏景回归

复习资料默认给原PDF，不默认讲解。某门课 topic=null、limit=20，逐文件编号，一条一个链接，项目间空行。大一下程序设计应返回5份、大学物理7份；全目录是9课程33份，不能拿搜索第一页当全库。下载用 download_url，不能用预览或学校管理页；学校外链可能新开标签，无法由本项目改变其外链策略。

散步/约会按 `activity:walk` / `activity:date` 等用途召回；点位允许交叉用途。一次查询多个标签是 AND，“建筑或者湖边”应分别查询后按 spot_id 合并。完整34点目录应合并 flower、architecture、foliage、waterside、landscape 五类，避免 limit=20 截断。草原、廊桥不能因为不是建筑就被丢弃。用途是基于原资料的推荐建议，不保证实时花况、安静或夜间安全。地图为原始像素标记，不编造GPS路线。

## 6. 团队测试与修改通道

三层权限分别验收：

1. **体验**：学校 Web 服务指定用户名单；成员用自己的校园身份登录主 Agent。
2. **修改**：团队空间/资源的普通协作编辑权限；应先改草稿和测试，未经负责人确认不要改正式渠道或共享凭证。
3. **代码/API**：仓库代码、本地虚构夹具和已授权公开 REST 可供团队联调；不需要共享腾讯云管理员账户。学校 Agent API/MCP 集成当前停用，不应把停用地址当可调用通道。

本轮负责人已提供四名拟添加成员。实际添加数量、保存/发布状态和成员本人验证结果应以操作回执为准；不能将“搜索并暂选”写成“权限已生效”。个人账号信息只在平台中核对，不保存到公开仓库。成员未亲自登录验证时，记录为“名单配置完成/本人待验”，而不是“保证随时能用”。

建议每人测试：赏花→选择花种→选点位；情侣散步→草地/廊桥→地图；明确课程→全部文件逐行下载；固定课表校验；固定通知预览和时间检查；事务官方摘要/课程demo消歧；固定学分审计。跨方向切换也应能正确路由。
